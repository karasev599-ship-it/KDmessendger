# KD Messenger

Отдельный фронтенд KD Messenger. Репозиторий предназначен для независимого деплоя и не содержит торговую панель KD Intelligence.

## Структура

- `index.html` — оболочка приложения и подключение модулей.
- `style.css` — интерфейс и адаптивные стили.
- `app.js` — авторизация, профиль, список диалогов и обмен сообщениями.
- Остальные `*.js` — профиль, контакты, медиа, realtime, уведомления, звонки, приватность и дополнительные функции.

## Backend

Фронтенд подключается к существующему проекту Supabase KD. Это означает, что фронтенд и деплой отделены, но backend пока общий с исходным проектом.

В браузере допустим только публичный publishable/anon key. **Никогда не добавляйте service-role key в клиентский код.** Доступ к данным должен ограничиваться Supabase RLS и проверками на стороне backend.

## Локальный запуск

Можно открыть `index.html` через локальный статический сервер. Для авторизации, сообщений и realtime нужен доступ к Supabase и корректно настроенные таблицы, политики RLS и Storage.

## Деплой на Vercel

1. Импортируйте этот репозиторий в Vercel как **новый проект**, отдельно от KD Intelligence.
2. Для обычного статического сайта оставьте Framework Preset как **Other**.
3. Build Command можно оставить пустой; Output Directory — корень проекта (`.`).
4. Выполните Deploy и проверьте вход, список чатов, отправку сообщений и обновления в реальном времени.

## Что ещё проверить перед использованием

- Провести проверку в браузере с реальной учётной записью Supabase.
- Убедиться, что схема БД, RLS и Storage policies соответствуют используемым модулями таблицам.
- Для стабильных аудио-/видеозвонков за пределами простых сетевых сценариев настроить TURN-сервер и безопасно передавать его параметры; TURN-учётные данные в репозитории не хранятся.
- Проверить мобильный интерфейс, повторное подключение и работу всех кнопок.

**Статус:** файлы перенесены; это ещё не подтверждение успешного браузерного тестирования или деплоя.
